WOrmLevel

WOrmLevel

new WOrmLevel(optopt) → {Object}

Description:

  • 操作資料庫(Level)

    回傳物件為EventEmitter，除各操作函數外另發出change與error兩事件，供呼叫端於單一處集中觀察資料異動與失敗。 事件僅為附加通知，其所送出之資訊皆另有正規管道(操作結果經resolve、整批性錯誤經reject、逐筆失敗經該筆之err欄位)， 故不監聽亦能取得完整資訊，且監聽與否不改變任何操作之回傳值。

    change事件，參數為(mode, data, res)，於資料實際異動成功後發出： mode為操作別字串，可為'insert'、'insertBulk'、'save'、'del'、'delAll'；save內若逐筆走自動插入則該筆另發出mode為'insert'之事件。 data為本次操作之輸入數據，delAll固定為null。 res為本次操作之回傳結果。 逐筆函數以整批為單位發出一次而不逐筆發出，select與selectByPk不發出本事件。

    error事件，參數為(mode, data, err)，於操作發生錯誤時發出： mode為操作別字串，可為'select'、'selectByPk'、'insert'、'insertBulk'、'save'、'del'、'delAll'。 data為本次操作之輸入數據，無輸入數據者為null。 err為錯誤訊息字串，內容與正規管道所送出者一致。 整批性錯誤於reject之前發出；逐筆失敗於該筆結果定案後發出，每筆一次。 insert、insertBulk、save與del因輸入本身導致之失敗(如原型為null之Date使複製拋錯、存取器拋錯)亦屬整批性錯誤，同樣於reject之前恰發出一次、不發出change事件、資料庫不變； 拋錯於複製建立之前者，data為呼叫端傳入之原值，其後者為複製；err為拋出者之原訊息(呼叫端自行拋出之值或訊息原樣通過，無法轉為字串者以固定訊息unknown error取代)，本套件不另行回顯數據內容。 註: 逐筆失敗時整批仍resolve，故收到本事件不表示該次呼叫失敗；正常結果(如查無數據、主鍵未命中、全數已存在)不發出本事件。

    註: 本套件之主鍵欄位固定為id，尚未支援指定其他欄位為主鍵。 註: level無條件寫入、無比較並交換亦無交易，故insert之[檢查主鍵不存在與寫入]與save之[查找主鍵與更新或插入]， 其原子性由本套件之序列化佇列提供；而LevelDB對資料庫目錄為OS層之獨佔鎖， 同一目錄無從由第二個實例或第二個行程開啟，故行程內序列化即等同全域互斥，詳見README之併發保證宣告。 註: 因獨佔鎖之故，用畢須以close()釋放，否則同目錄無法再被開啟。 註: 數據以JSON存值，Date存入後為ISO字串；insert、insertBulk與save寫入之Date年份須介於0000-9999，範圍外(如new Date(8.64e15))整批reject，詳見各函數與README。

    字串良構(w-orm系列規則，wsemi之chkOrmStr與chkOrmData): level之鍵經UTF-8編碼，孤立代理字元(String.prototype.isWellFormed()為false)被改寫為U+FFFD， 使不同主鍵落到同一個鍵而覆蓋、誤刪、誤命中他筆；值為JSON雖可保真，全系列仍一律拒收。於任何讀取與寫入之前拒收：

    1. 主鍵(id)不得含孤立代理字元與NUL，不隨autoGenPk改變；
    2. 寫入資料(insert、insertBulk、save)之字串值與鍵名(含巢狀物件、陣列元素、Map與Set之項目、Error與RegExp之文字)不得含孤立代理字元，值與鍵名之NUL不拒；
    3. opt.url、opt.db、opt.cl含孤立代理字元者於建構時throw，訊息為invalid opt.<名>: string contains lone surrogate。 處置與無效主鍵同形：insert與insertBulk整批reject而不寫入任何一筆(error事件先於reject)，save與del該筆ok為0並附err(同批其他筆照常)，selectByPk回null； 訊息為固定詞彙而不回顯值：invalid id: 原因 at [data[k].id]、invalid data: 原因 at [data[k].路徑](k為批次索引，單一物件為0；不合格之鍵名以標示)， 原因為string contains lone surrogate、string contains NUL(僅主鍵)、not a string或string is empty(del之id未給、非字串或空字串)。 U+FFFD本身與成對代理(emoji等)為良構，照常接受。既有資料不遷移，檢出與清除法見README。

    診斷輸出(w-orm系列規則，選項名稱與語意同w-serv-orm): 本套件唯一會自行輸出之情形，是change或error事件之訂閱函數拋錯被攔下時 (攔下後不影響本次操作之回傳與事件發出)，所有輸出皆經單一出口(src/getDiag.mjs)，其餘情形不輸出：

    1. 預設只輸出固定標籤與不含個資之摘要，如console.log('change handler threw', { mode: 'insert', errType: 'Error' })與console.log('error handler threw', { mode, errType, errCode })， 標籤為change handler threw或error handler threw，mode為操作別，errType為拋出值之型別(string、number、object等)或錯誤類別名稱(建構子名稱，限識別字樣式^[A-Za-z][A-Za-z0-9_]{0,39}$，不合者列為Error)， errCode僅在拋出值之自有資料屬性code為機器代碼(ENOENT類之E開頭純大寫字母、E2BIG、ERR_xxx、LEVEL_xxx、絕對值至99999之整數)時列出； 不含資料值、主鍵、使用者識別、錯誤訊息、堆疊與路徑，亦不執行拋出值上之存取器。
    2. opt.logDetail為true時，還原為舊版輸出console.log(拋出值)(含錯誤訊息與堆疊，單一引數、無標籤)，供除錯；輸出的是拋出值之遮罩拷貝(見下述第5點)。
    3. opt.funLog為函數時，診斷輸出只交給它而不寫console，呼叫為funLog(label, safe, detail)：label為上述標籤，safe為上述摘要，detail為訂閱函數拋出值之遮罩拷貝(含錯誤訊息，供使用端自行遮罩或轉送；拷貝不改動原物件，原地修改它不影響操作之回傳與事件參數)； 與logDetail並給時以funLog為準。funLog拋錯、回傳之promise被reject皆被吞下，不影響操作。
    4. opt.logDetail與opt.funLog於建構時取固定快照；型別錯誤(logDetail非布林true、funLog非函數)者忽略並用預設，不throw(同useCache、autoGenPk)；讀取該選項拋錯者亦同。
    5. 資料庫位置(opt.url、opt.db、opt.cl組成之儲存位址，及其絕對路徑與正反斜線形式)視同連線字串：預設輸出不含細節，logDetail與funLog之細節中出現者(如後端I/O錯誤訊息經訂閱函數轉拋)以***取代，屬性值、屬性鍵與Symbol描述皆然；本套件無帳密選項。 遮罩拷貝複製純物件、類別實例、陣列、Error與Date為內建原型之副本(不呼叫存取器與建構子)，函數、Proxy、二進位資料、Map與Set等以標記字串代替，深度超過8或節點超過5000者以[Truncated]代替。 註: 診斷輸出自身拋錯(如拋出值無法被格式化)被吞下，不使操作拋錯(格式化失敗時改輸出標籤與(unprintable))；各操作之resolve與reject內容、事件參數與發出時機不受任何診斷選項影響。 註: 各操作reject、逐筆err欄位與error事件內之訊息文字(如can not insertBulk by existed id[...]、後端I/O錯誤原文)屬回傳契約，不在診斷輸出之範圍，訂閱函數自行轉拋時該文字會出現在其拋出值中(位址名稱於logDetail與funLog之細節遮罩)。

(async, static) delAllCore(findopt) → {Promise}

Description:

  • 依條件刪除多筆數據(破壞性操作，須審慎使用，非必要不用；刪除單筆請用del)

    使用須知:

    1. 不給條件即刪除全部數據: find未給、為undefined或為{}時，刪除資料表內全部數據，不另行確認。 給了條件才是部分刪除。
    2. 傳了值卻不是條件物件(null、陣列含[]與[{...}]、字串、數值、布林、函數、Date、RegExp、Map、Set、類別實例等) 一律整批reject，不視為{}，不刪除任何數據。
    3. 條件僅支援系列白名單: 欄位等值{欄:純量}(多欄為AND)、欄位運算子$eq $ne $gt $gte $lt $lte(值為純量)與 $in $nin(值為純量陣列)、文件層$and $or(值為條件物件之非空陣列)。純量為字串(不含NUL字元與孤立代理字元)、有限數字、布林、有效Date(年份須介於0000-9999，範圍外整批reject，見第6點)； null僅可用於欄位等值、$eq、$ne。白名單外之運算子($not $nor $regex $options $exists $where $expr $like $ilike等)、 欄位層$and/$or、子查詢、函數值、Symbol鍵、undefined值、空的$nin/$and/$or等一律整批reject， 訊息為invalid find: 原因 at [路徑]，且不刪除任何數據。
    4. 與select共用同一檢核與同一條件，select(find)命中之數據即本函數刪除之數據； 建議先以select(find)確認命中範圍再刪除。
    5. 條件值若來自可能為undefined、null或空陣列之變數，呼叫端須先自行判斷；undefined值會reject而非被忽略， 空的$nin會reject，$in:[]則為恆假(刪除0筆)。
    6. 語意差異(依後端，見README): MongoDB式: $ne(比較值非null時)與$nin會命中欄位為null或缺欄之數據，$ne:null則排除之； 欄名同於Object.prototype成員(constructor、toString等)者，數據無此自有欄位時視為缺欄； Date條件於本後端轉為ISO字串後以字典序比較(與字串型欄位亦會比較)：條件內任何位置之Date其年份須介於0000-9999， 範圍外(年份小於0或大於9999，如new Date(8.64e15)、new Date(-8.64e15))整批reject，訊息為invalid find: Date year is out of range 0000-9999 at [路徑]， 不回顯值，不讀取、不刪除任何數據；數據側自1.0.34起insert、insertBulk與save寫入時已拒收範圍外Date， 但資料庫內既有之範圍外Date字串(舊版以new Date(8.64e15)作永不過期哨兵存入者)仍無法以Date條件正確比較 (例如{t:{$lt:現在}}會命中哨兵並將其刪除)，請自行清理或改寫，見README。 需明確表達時可用可攜寫法: 排除NULL為{$and:[{f:{$ne:null}},{f:{$ne:x}}]}，含NULL為{$or:[{f:null},{f:{$ne:x}}]}。

    n與nDeleted皆為實際刪除筆數，不取全表筆數。條件無命中時回{n:0,nDeleted:0,ok:1}，不視為錯誤。

(async, static) insertBulkCore(data) → {Promise}

Description:

  • 批次插入數據，全批視為一個單位，全部插入成功或一筆都不寫入 註: 本函數非insert之加速版，兩者衝突政策不同。insert於主鍵已存在時跳過該筆而整批ok為1， 本函數則整批reject且不寫入任何一筆；同批含重複主鍵者亦視為衝突。確無衝突時兩者結果相同 註: 於本套件不會較insert快，因兩者皆為一次批次取值與一次批次寫入， 提供本函數係為與其他w-orm系列套件維持同一組函數，令呼叫端得於各套件間替換而不須改寫呼叫 註: 數據內任何深度之Date年份須介於0000-9999，範圍外(如new Date(8.64e15))整批reject且不寫入任何一筆，規則同insert，詳見insert與README

  • 序列化本實例之操作

    level無條件寫入、無比較並交換亦無交易，故insert之[檢查主鍵不存在與寫入]與save之[查找主鍵與更新或插入]， 其原子性只能由序列化達成。採Promise鏈而非[布林旗標配合輪詢等待]，係因後者之[檢查旗標]與[設定旗標]之間隔有await， 並非原子之test-and-set，多個等候者之輪詢若落在同一批timer觸發即會同時進入臨界區； 且輪詢函數逾時後為resolve而非reject，等滿即照樣放行。Promise鏈為嚴格FIFO且無逾時放行，由結構保證互斥。 select亦納入序列化，令其不致與寫入之批次替換交錯。

WOrmLevel

WOrmLevel

new WOrmLevel(optopt) → {Object}

Description:

  • 操作資料庫(Level)

    回傳物件為EventEmitter，除各操作函數外另發出change與error兩事件，供呼叫端於單一處集中觀察資料異動與失敗。 事件僅為附加通知，其所送出之資訊皆另有正規管道(操作結果經resolve、整批性錯誤經reject、逐筆失敗經該筆之err欄位)， 故不監聽亦能取得完整資訊，且監聽與否不改變任何操作之回傳值。

    change事件，參數為(mode, data, res)，於資料實際異動成功後發出： mode為操作別字串，可為'insert'、'insertBulk'、'save'、'del'、'delAll'；save內若逐筆走自動插入則該筆另發出mode為'insert'之事件。 data為本次操作之輸入數據，delAll固定為null。 res為本次操作之回傳結果。 逐筆函數以整批為單位發出一次而不逐筆發出，select與selectByPk不發出本事件。

    error事件，參數為(mode, data, err)，於操作發生錯誤時發出： mode為操作別字串，可為'select'、'selectByPk'、'insert'、'insertBulk'、'save'、'del'、'delAll'。 data為本次操作之輸入數據，無輸入數據者為null。 err為錯誤訊息字串，內容與正規管道所送出者一致。 整批性錯誤於reject之前發出；逐筆失敗於該筆結果定案後發出，每筆一次。 insert、insertBulk、save與del因呼叫端給的值不可讀(讀取即拋錯，如已撤銷之Proxy、陷阱或存取器拋錯、複製階段之巢狀不可讀值、原型為null之Date使複製拋錯)導致之失敗亦屬整批性錯誤，同樣於reject之前恰發出一次、不發出change事件、資料庫不變； 此類拒絕發生於入口階段(讀取option或data、複製data)，data固定為null(不把不可讀之值交給訂閱函數)，err為固定詞彙invalid <名稱>: must be a readable value(不含拋出者之原訊息與值，詳見下方呼叫端給的值之可讀性)； 其餘整批性錯誤(如主鍵衝突、Date範圍外、主鍵檢核不合格)data為本次操作之數據複本，err中後端或使用端回呼拋出之外來值依下列診斷規則處置。 註: 逐筆失敗時整批仍resolve，故收到本事件不表示該次呼叫失敗；正常結果(如查無數據、主鍵未命中、全數已存在)不發出本事件。

    註: 本套件之主鍵欄位固定為id，尚未支援指定其他欄位為主鍵。 註: level無條件寫入、無比較並交換亦無交易，故insert之[檢查主鍵不存在與寫入]與save之[查找主鍵與更新或插入]， 其原子性由本套件之序列化佇列提供；而LevelDB對資料庫目錄為OS層之獨佔鎖， 同一目錄無從由第二個實例或第二個行程開啟，故行程內序列化即等同全域互斥，詳見README之併發保證宣告。 註: 因獨佔鎖之故，用畢須以close()釋放，否則同目錄無法再被開啟。 註: 數據以JSON存值，Date存入後為ISO字串；insert、insertBulk與save寫入之Date年份須介於0000-9999，範圍外(如new Date(8.64e15))整批reject，詳見各函數與README。

    字串良構(w-orm系列規則，wsemi之chkOrmStr與chkOrmData): level之鍵經UTF-8編碼，孤立代理字元(String.prototype.isWellFormed()為false)被改寫為U+FFFD， 使不同主鍵落到同一個鍵而覆蓋、誤刪、誤命中他筆；值為JSON雖可保真，全系列仍一律拒收。於任何讀取與寫入之前拒收：

    1. 主鍵(id)不得含孤立代理字元與NUL，不隨autoGenPk改變；
    2. 寫入資料(insert、insertBulk、save)之字串值與鍵名(含巢狀物件、陣列元素、Map與Set之項目、Error與RegExp之文字)不得含孤立代理字元，值與鍵名之NUL不拒；
    3. opt.url、opt.db、opt.cl含孤立代理字元者於建構時throw，訊息為invalid opt.<名>: string contains lone surrogate。 處置與無效主鍵同形：insert與insertBulk整批reject而不寫入任何一筆(error事件先於reject)，save與del該筆ok為0並附err(同批其他筆照常)，selectByPk回null； 訊息為固定詞彙而不回顯值：invalid id: 原因 at [data[k].id]、invalid data: 原因 at [data[k].路徑](k為批次索引，單一物件為0；不合格之鍵名以標示)， 原因為string contains lone surrogate、string contains NUL(僅主鍵)、not a string或string is empty(del之id未給、非字串或空字串)。 U+FFFD本身與成對代理(emoji等)為良構，照常接受。既有資料不遷移，檢出與清除法見README。

    主鍵(id)之未帶與給了(w-orm系列規則，帳本R-PKGIVEN-01)：只有id為undefined、null、空字串(含鍵不存在)視為未帶，autoGenPk為true時自動產生， 為false時整批reject(save亦然，不降為逐筆)，訊息為can not <入口> by data[k] without valid id when autoGenPk is false；其餘一律視為給了， 給了而非字串(數字、布林、物件、陣列、String包裝物件、Symbol、BigInt等)者不補值亦不替換為新產生之主鍵(主鍵為資料之身分，給了錯值卻換成新主鍵寫入，事後無從對應)， 依各入口既有之失敗通道拒絕，通道不隨autoGenPk改變，訊息為固定詞彙invalid id: not a string at data[k].id： insert與insertBulk整批reject(error事件於reject之前恰一次、不發change、資料庫不變)，save與del該筆ok為0並附err，selectByPk回null。

    主鍵只認自有可列舉之資料屬性(w-orm系列規則，帳本R-PKOWN-01)：列之id為繼承(原型鏈上，如Object.create({ id })或類別實例原型上之getter與資料屬性，不論值為字串、數字或物件) 或自有不可列舉者，視為未帶(同undefined、null、空字串)：autoGenPk為true時補新主鍵(以Object.defineProperty定義為自有可列舉之資料屬性，不經賦值，原型上之setter不被執行、凍結之原型不致拋錯)， 為false時依上述未帶之整批reject；del視為未給主鍵(該筆ok為0，訊息invalid id: not a string at [data[k].id])。繼承值不被當成主鍵，故不再有「以繼承值為鍵寫入無id欄之列」， 亦不再有與庫內同值之既有列衝突(insert跳過、insertBulk整批reject、save覆寫、del刪除)。先以既有路徑取值，值為未帶者短路，只有值為給了才查描述子(不呼叫getter、不多讀有效輸入)； 繼承之存取器id仍照既有路徑讀1次(拋錯者為固定詞彙invalid data: must be a readable value)，其回傳之值不被使用(含不可讀之值)。selectByPk收純量pk，不適用；非主鍵欄之繼承欄位之處置不變。

    呼叫端給的值之可讀性(w-orm系列規則，帳本R-PROBE-01，用wsemi之chkReadable)：呼叫端給的資料(data)、選項(opt.url、opt.db、opt.cl、opt.useCache、opt.autoGenPk、option.returnList)、 selectByPk之pk與經類別實例原型上之存取器讀出之id(存取器自身拋錯者；其回傳之值屬繼承，視為未帶而不被探測，見上)，若為讀取即拋錯之值(已撤銷之Proxy、Symbol.toStringTag或陷阱拋錯者、單元素陣列之[0]存取器拋錯者等)， 走各入口既有之失敗通道(寫入入口與selectByPk為error事件恰一次後reject、資料庫不變，建構為同步throw)，訊息為固定詞彙invalid <名稱>: must be a readable value， 不含拋出者之原訊息與值，亦不轉出呼叫端物件(存取器、Proxy陷阱、巢狀值)拋出之文字；可讀而型別不符者行為不變(輸入無效早退、查無數據、選項採忽略)。名稱依拒絕之處：

    1. 選項容器本身不可讀(opt或option為已撤銷之Proxy、get陷阱或Symbol.toStringTag拋錯者，讀其成員即拋錯)：invalid opt(建構)、invalid option(insert與save之option)；
    2. 容器可讀而其成員之讀取拋錯(拋錯之存取器，或僅對該鍵拋錯之get陷阱)：invalid opt.<名>(建構)、invalid option.returnList、invalid option.autoInsert；opt.<名>與option.returnList之值本身不可讀者名稱同(option.autoInsert只取真值，不檢其值之可讀性)；
    3. 資料不可讀(含複製階段之巢狀不可讀值：資料內之id、列之成員、陣列其後之元素、各欄為已撤銷之Proxy或拋錯之存取器、複本原型上拋錯之存取器、原型為null之Date、過深之巢狀等； 複製、補主鍵之指派與良構檢核讀取複本時拋錯者不分頂層與巢狀一律同詞彙)：invalid data；
    4. selectByPk之pk不可讀：invalid pk(可讀而非字串者回null)。 入口階段之拒絕(上列1~3)，error事件之data為null；opt.logDetail與opt.funLog由wsemi之getDiag處置(診斷出口永不失敗，不經上述)。 已關閉(close後)之實例於入口先拒絕，error事件之data為呼叫端傳入之原值，惟其型別標籤不可讀者為null。

    診斷輸出與遮罩(w-orm系列規則，選項名稱與語意同w-serv-orm；遮罩、摘要與出口皆用wsemi之共用實作getDiag，規則見wsemi之getDiag說明與規格〈診斷輸出與遮罩〉)： 本套件唯一會自行輸出之情形，是change或error事件之訂閱函數拋錯被攔下時(攔下後不影響本次操作之回傳與事件發出)，所有輸出皆經單一出口(wsemi之getDiag)，其餘情形不輸出：

    1. 預設只輸出固定標籤與不含個資之摘要，如console.log('change handler threw', { mode: 'insert', errType: 'Error' })與console.log('error handler threw', { mode, errType, errCode })， 標籤為change handler threw或error handler threw，mode為操作別，errType為拋出值之型別(string、number、object等)或錯誤類別名稱， errCode僅在拋出值之自有資料屬性code為wsemi明列之機器代碼(libuv系統錯誤名稱、Node常見代碼、abstract-level與classic-level之LEVEL_xxx)時列出； 不含資料值、主鍵、使用者識別、錯誤訊息、堆疊與路徑，亦不執行拋出值上之存取器。
    2. opt.logDetail為true時，改輸出console.log(標籤, 細節)，細節為訂閱函數拋出值之遮罩拷貝(含錯誤訊息與堆疊)，供除錯。
    3. opt.funLog為函數時，診斷輸出只交給它而不寫console，呼叫為funLog(label, safe, detail)：label為上述標籤，safe為上述摘要，detail為訂閱函數拋出值之遮罩拷貝(含錯誤訊息，供使用端自行遮罩或轉送；拷貝不改動原物件，原地修改它不影響操作之回傳與事件參數)； 與logDetail並給時以funLog為準。funLog拋錯被吞下，回傳之原生Promise被reject時標記為已處理(一般thenable之then不被呼叫)，皆不影響操作。
    4. opt.logDetail與opt.funLog於建構時取固定快照；型別錯誤(logDetail非布林true、funLog非函數)者忽略並用預設，不throw(同useCache、autoGenPk)；讀取該選項拋錯者亦同。
    5. 資料庫位置(opt.url、opt.db、opt.cl組成之儲存位址，及其絕對路徑與正反斜線形式)視同連線字串：預設輸出不含細節，logDetail與funLog之細節中出現者(如後端I/O錯誤訊息經訂閱函數轉拋)以***取代，屬性值、屬性鍵與Symbol描述皆然；本套件無帳密選項。 遮罩拷貝複製純物件、類別實例、陣列、Error、Map與Set等為內建原型之副本(不呼叫存取器與建構子)，函數、Proxy、二進位資料等以標記字串代替，過深或過大者以[Truncated]代替，細節見wsemi之maskDiagCopy。
    6. 對外錯誤值不含憑證：整批reject之值、error事件之錯誤與訊息引數、逐筆結果之err欄位，凡為外來值(後端、使用端存取器或回呼拋出者)，含憑證(連線網址之帳密、password=或token=類鍵值對、Bearer權杖等)時以***取代，不含憑證者原物件交出(身分不變)，細節見wsemi之maskDiagErr； 只遮憑證，不遮儲存路徑與單獨帳號(對外錯誤值之路徑屬回傳契約，如err.path)；本套件自身以固定詞彙組成之訊息(如can not insertBulk by existed id[...]、invalid data: ...)不經遮罩。 註: 診斷輸出自身拋錯(如拋出值無法被格式化)被吞下，不使操作拋錯(格式化失敗時改輸出標籤與(unprintable))；各操作之resolve與reject內容、事件參數與發出時機不受任何診斷選項影響。 註: 各操作reject、逐筆err欄位與error事件內之固定詞彙訊息文字(如can not insertBulk by existed id[...])屬回傳契約，不在診斷輸出之範圍，訂閱函數自行轉拋時該文字會出現在其拋出值中(位址名稱於logDetail與funLog之細節遮罩)。

(async, static) delAllCore(findopt) → {Promise}

Description:

  • 依條件刪除多筆數據(破壞性操作，須審慎使用，非必要不用；刪除單筆請用del)

    使用須知:

    1. 不給條件即刪除全部數據: find未給、為undefined或為{}時，刪除資料表內全部數據，不另行確認。 給了條件才是部分刪除。
    2. 傳了值卻不是條件物件(null、陣列含[]與[{...}]、字串、數值、布林、函數、Date、RegExp、Map、Set、類別實例等) 一律整批reject，不視為{}，不刪除任何數據。
    3. 條件僅支援系列白名單: 欄位等值{欄:純量}(多欄為AND)、欄位運算子$eq $ne $gt $gte $lt $lte(值為純量)與 $in $nin(值為純量陣列)、文件層$and $or(值為條件物件之非空陣列)。純量為字串(不含NUL字元與孤立代理字元)、有限數字、布林、有效Date(年份須介於0000-9999，範圍外整批reject，見第6點)； null僅可用於欄位等值、$eq、$ne。白名單外之運算子($not $nor $regex $options $exists $where $expr $like $ilike等)、 欄位層$and/$or、子查詢、函數值、Symbol鍵、undefined值、空的$nin/$and/$or等一律整批reject， 訊息為invalid find: 原因 at [路徑]，且不刪除任何數據。
    4. 與select共用同一檢核與同一條件，select(find)命中之數據即本函數刪除之數據； 建議先以select(find)確認命中範圍再刪除。
    5. 條件值若來自可能為undefined、null或空陣列之變數，呼叫端須先自行判斷；undefined值會reject而非被忽略， 空的$nin會reject，$in:[]則為恆假(刪除0筆)。
